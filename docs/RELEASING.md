# Releasing Picvert

Step-by-step for cutting a new release that auto-updates installed users.

## One-time setup

### 1. GitHub repository secrets

Go to **Settings → Secrets and variables → Actions** and add:

| Secret | Value | Where to get it |
|---|---|---|
| `TAURI_SIGNING_PRIVATE_KEY` | full content of `~/.tauri/picvert.key` | generated by `cargo tauri signer generate` |
| `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` | empty (or your password) | the `--password` you used (we used empty) |

⚠️ **Never** commit `~/.tauri/picvert.key`. Only the public key (already in `tauri.conf.json`) should be in the repo.

### 2. Apple code signing (optional but recommended for macOS)

Without it, users see "unidentified developer" on first launch.

1. Sign up: https://developer.apple.com/programs/ ($99 / year)
2. Create an Application + Installer certificate in Xcode → Settings → Accounts → Manage Certificates
3. Export them as `.p12` and add to GitHub secrets:
   - `APPLE_CERTIFICATE` — base64 of the `.p12`
   - `APPLE_CERTIFICATE_PASSWORD` — the .p12 password
   - `APPLE_SIGNING_IDENTITY` — e.g. `Developer ID Application: Your Name (TEAM_ID)`
   - `APPLE_ID` — your Apple ID email
   - `APPLE_PASSWORD` — an app-specific password from https://appleid.apple.com
   - `APPLE_TEAM_ID` — your team ID
4. Tauri will automatically sign + notarize when these are set.

### 3. Windows code signing (optional)

OV cert: ~$200/year; EV cert: ~$300-700/year. Can ship unsigned at the cost of SmartScreen warnings.

When you have a `.pfx`:
- `WINDOWS_CERTIFICATE` — base64 of the `.pfx`
- `WINDOWS_CERTIFICATE_PASSWORD` — the password

## Cutting a release

```bash
# 1. Bump versions in lockstep
#    - pyproject.toml         (Python package)
#    - src-tauri/tauri.conf.json  (productName.version)
#    - src-tauri/Cargo.toml   (package.version)

# 2. Commit + tag
git add -A
git commit -m "Release v1.2.0"
git tag v1.2.0
git push origin main --tags
```

That's it. The `Release` workflow will:

1. Build the Python `picvert-engine` binary on each platform
2. Run all tests
3. Build the Tauri bundle (`.dmg` on macOS, `.exe`/`.msi` on Windows)
4. Sign the update payload using your `TAURI_SIGNING_PRIVATE_KEY`
5. Generate `latest.json` (the manifest auto-updater clients look for)
6. Publish a GitHub Release with all artifacts

## How the auto-updater works

When a Picvert install runs, the Tauri updater plugin:

1. Hits `https://github.com/Akxan/picvert/releases/latest/download/latest.json`
2. Reads the version + per-platform URL + signature
3. If newer than the running version → asks the user to update (a dialog, controlled by `dialog: true` in the config)
4. Downloads the new `.app.tar.gz` / `.exe` from GitHub
5. Verifies the signature against the embedded **public** key
6. Replaces the app and prompts a restart

The signature step is critical: even if someone hijacks the GitHub URL or your Releases, they cannot push a payload that was not signed by your private key.

## Manual smoke test before tagging

```bash
# Python tests
pytest -q

# Build sidecar locally
./scripts/build_sidecar.sh

# Open the dev shell (needs sidecar built first)
cargo tauri dev
```

If the dev shell launches, the engine pings, formats list shows up, and you can convert one PNG to PDF — you're good to tag.
